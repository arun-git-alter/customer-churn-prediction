01 / ARCHITECTURE

One model, a small API, a static interface.

The browser collects the customer profile and sends JSON to Flask. Flask validates the request, constructs the model input in its expected feature order, and returns a prediction generated by the saved model artifact.

03 / EDA & PREPARATION

Explore, clean, and prepare the inputs.

Notebooks cover data understanding, exploratory analysis, logistic regression, Random Forest experiments, tuning, and feature analysis. The modeling code identifies categorical and numeric columns, uses one-hot encoding for categories, and scales numeric columns in the logistic regression workflow.

A

Preprocessing

Notebook pipelines use ColumnTransformer and OneHotEncoder. The API validator separately checks allowed category values, finite numeric inputs, and the expected feature list.

B

Feature engineering

The source artifacts show categorical encoding and numerical handling in model pipelines. No additional derived form features are required by the prediction API.

Class imbalance: one feature-analysis experiment sets class_weight="balanced". The available artifacts do not establish that this is the configuration in the deployed calibrated model.

04 / MODEL DEVELOPMENT

Compare, calibrate, then serve.

01

Model experiments

Notebooks include Logistic Regression and Random Forest workflows, with stratified train/test splitting and cross-validation experiments.

02

Feature analysis

Feature importance, permutation importance, and SHAP analyses are present in the feature-analysis notebook. These are exploratory explanations, not causal findings.

03

Probability calibration

The model configuration identifies sigmoid calibration. The saved configuration names the positive class as Yes and the classification threshold as 0.5.

04

Prediction output

The API obtains the probability for class Yes, applies the 0.50 threshold for the binary result, and assigns one of five risk categories using probability bands.

No performance scores are presented here. Notebook outputs include results from different experiments and splits; the repository does not identify a single verified evaluation report for the deployed artifact.

05 / API & COMMUNICATION

A predictable request and response.

POST/predictapplication/json

The frontend sends the 19 model fields as JSON. The backend rejects missing or unexpected fields, invalid categories, non-finite numbers, and out-of-range tenure. On success it responds with a prediction object.

churn_probabilityNumber · probability for the positive class
churn_predictionInteger · 0 or 1 using the 0.50 threshold
churn_labelString · Yes or No
risk_categoryString · one of five probability bands
Very Lowunder 20%
Low20% to under 40%
Medium40% to under 60%
High60% to under 80%
Very High80% and above

For GitHub Pages, set the API base URL in frontend/static/js/config.js. The Flask CORS allowlist includes this project’s GitHub Pages origin and localhost origins.

06 / LIMITATIONS & NEXT STEPS

Use the score with context.

  • A churn probability is a model estimate, not a guarantee or a causal explanation.
  • Risk categories are fixed probability intervals; they are not calibrated business outcomes.
  • Evaluation metrics and the chosen threshold should be reviewed against the exact deployed model and the costs of missed churn versus unnecessary outreach.
  • Future work could add a versioned evaluation report, monitored calibration, stronger model explanations in the live API, and documented deployment configuration.
